## 0.5.0：配置管理闭环

### 范围与行为

| 能力 | 建议行为 | 关键验收 |
| --- | --- | --- |
| 新建 | 创建未启用的配置，沿用正文非空、名称与 id 校验 | 新建不改变当前注入；保存后可手动启用 |
| 复制 | 从已有配置复制已保存正文与规则，生成新 id | 改副本不影响原配置；有草稿时先说明复制哪份内容 |
| 重命名 | 只改显示名称，id 保持稳定 | 当前配置引用、正文和规则保持不变 |
| 删除 | 显式确认；不能删除最后一套；删除启用项时明确展示回退目标 | 回退到可用配置，下一次组装可核对；失败不改内存 |
| 导出 | 导出带格式版本的 JSON，默认只含已保存配置 | 不导出快照、历史求值或运行时路径；提示文件含提示词正文 |
| 导入 | 校验后预览，再一次性写入；默认追加并为冲突 id 生成新 id | 不自动启用、不覆盖原项；任一项非法或合并后超过 20 套则整体拒绝 |

保留现有附加规则文本和注入方式。0.5.0 不同时改变“配置管理”和“提示词如何分段”的行为。

### 技术任务

1. 提取 `lib/store.js`，集中处理原子写、格式校验、版本识别和迁移备份；兼容无格式版本的 0.4.9 数据。
2. 扩展配置动作：create、duplicate、rename、delete、import；保持现有 save、activate、settings.update 可用。
3. 导入只接受数据 JSON，不执行或解释文件内的脚本/指令。单次导入上限按最多 20 套、每套两个 64000 UTF-16 单元字段及最坏 JSON 转义单独计算，避免沿用单条保存的 788000 字节预算。
4. 增加配置编辑版本校验：多窗口编辑同一项时，过期保存返回冲突并保留草稿，避免后保存者无提示覆盖他人修改；轮询 revision 不用作编辑锁。
5. 前端在现有页面增加管理按钮和导入预览，保留草稿保护、请求顺序控制及增量轮询。

### 验收门槛

- 新建→编辑→保存→启用→下一次组装可核对，重启后仍一致。
- 导出→在隔离目录导入→数据往返一致，原有配置与启用项不被隐式替换。
- 覆盖最后一项删除、启用项删除、重复 id、中文/emoji、超限、多窗口冲突、磁盘写入失败。
- 旧数据迁移前保留可恢复副本；回滚时使用匹配版本的数据备份，不承诺任意新格式自动兼容旧代码。
- 空闲增量响应保持小体积；现有 0.4.9 关键行为不回退。

## 0.5.1：独立规则库

1. 增加规则集的新建、编辑、复制、删除与导入导出，配置通过有序的 `ruleIds` 引用；规则内容不在多个配置间重复存储。
2. 保留旧 `profiles[].rules` 作为该配置自身的附加规则，避免自动迁移导致文本重复注入。
3. 将正文与规则拆成独立 section，分别可开关；保证已迁移方案的文本和顺序有明确兼容规则，并在快照中可核对。
4. 删除被引用规则时展示受影响配置并默认阻止删除；用户先解除引用，再删除规则。
5. 规则与配置采用同一原子数据快照，或有明确的事务恢复设计，避免两个 JSON 文件分别写入后只成功一半。

验收：两个配置引用同一规则、顺序切换、禁用规则、解除引用、重启恢复和写入失败均保持引用一致；不写入或覆盖 AGENTS.md、CLAUDE.md。

## 后续技术验证

- **本地指令勾选**：先确认可信 cwd 来源、宿主已加载哪些文件、真实路径与符号链接边界，再确定扫描范围和去重规则。
- **按会话快照**：先验证宿主与客户端能否提供一致的会话标识；不能可靠获取时继续标明进程作用域。
- **处理差异摘要**：在有界内存中展示本次段数、字数和处理统计，不建立提示词历史日志。
