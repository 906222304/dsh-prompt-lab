# Prompt Lab 下一步实施规划

> 日期：2026-11-06；基线：`dsh-prompt-lab@0.4.8`，Git `f58cee8`。
> 本轮产物是规划文档，尚未实施功能或修复。代码行号均指该基线。

> 2026-11-06 实施更新：0.4.9 已热加载到当前 desktop profile，43 项自动测试、真实宿主隔离联调与在线前后端资源校验已通过；配置保持不变。桌面画面尚未直接验收，npm 尚未发布。
> 最新后续范围见 [0.4.9 之后的实施路线](0.5-roadmap.md)：0.5.0 先做配置管理闭环，0.5.1 再做独立规则库。以下分析与估时保留为实施前基线。

## 1. 建议结论

先交付 **0.4.9 稳定性版本**，再交付 **0.5.0 配置管理与独立规则库**。本地指令扫描、更多组装策略等放到后续版本，在宿主接口确认后推进。

继续采用现有的两个 Cordis 插件行、一个浏览器面板和本地 HTTP 接口。保留无第三方运行时依赖、只写插件数据目录、不改宿主源码、不记录提示词事件历史的约定。

旧 `docs/migration-plan.md` 可作为能力清单，但不能继续作为实施基线：它针对 0.4.2、14 个测试，且把 settings 和组装改写视为尚未实现；当前 0.4.8 已有这些能力的一部分。

## 4. 优先修复清单

以下是源码事实或最小探针结果；宿主实际调用哪一种事件签名仍需联调确认。

| 优先级 | 证据 | 问题与建议验收 |
| --- | --- | --- |
| P0 | `lib/index.js:31-39,65-72` | `enabled=false` 或空正文会在监听器注册前 return。应分开定义“停止自定义提示词注入”和“停止观察/过滤”；若仅关注入，仍能看到宿主快照并应用独立设置。整条插件行停用时则明确显示该能力不可用。 |
| P0 | `lib/index.js:70` | next 仅在参数数量至少为 3 时识别。探针 `(assembly,next)` 中 next 未被调用。先确认宿主契约，再兼容已确认的两参/三参形态，各自验证仅调用一次且使用其返回结果。 |
| P0 | `lib/ui.js:16,85-88`、`lib/state.js:16,475-480` | 字段上限按字符、HTTP 上限按字节，当前限制为 276000 字节；两段各 64000 个“中”的合法保存请求实际为 384055 字节。统一限制口径，并覆盖中文、emoji、JSON 转义字符及真正超限输入。 |
| P1 | `lib/state.js:127-142` | 若合法配置文件没有 `default`，同时 selected 缺失或失效，当前仍保持 selected=`default`，无法选中实际配置。回退到首个合法 profile，并测试不含内置 id 的导入数据。 |
| P1 | `lib/state.js:375-392`、`client.js:326-328` | contexts 共享截断额度，但条目无 truncated 标记，总标志也只检查 sections。探针中 context 原长 17、保留 0，总标志仍为 false。两类条目统一记录原长、保留量与截断状态。 |
| P1 | `lib/state.js:35,356-399`、`client.js:409-411` | 最近一次 assembly 是进程全局单份，Panel 未传会话标识；当前不能保证快照属于所在页签的会话。近期先清楚标为“进程最近一次快照”；宿主有可靠 sessionId 后，再实现有容量上限的按会话存储与查询。 |
| P1 | `client.js:173-210,229-245` | GET 与 POST 独立进行，缺少旧响应丢弃机制；配置切换会直接丢弃草稿，启用动作也会重载已存文本。补 dirty 状态、离开/启用时的明确选择、请求序号或版本校验，防止旧 GET 覆盖 POST 结果。该项为静态发现，交互复现待补。 |

| P1 | `package.json` 的 files、`references/README.zh-CN.md:14` | 发布包包含参考说明，却未包含其依赖的提取脚本；离线示例还把源码目录写成 prompt-lab。明确命令仅适用于源码检出，或同步调整脚本发布方式，并修正示例。 |

组装异常处理应区分来源：插件自己的过滤或快照失败可返回未处理结果；下游 `next()` 的错误应按宿主契约传播。旧草案要求“下游抛错时回退”，未经验证不应直接采用，否则可能掩盖真正的宿主组装失败。

## 5. 实施顺序与交付物

### M1：0.4.9 稳定性与发布整理，预计 2–3 人日

1. 建立以 0.4.8 为准的宿主契约记录：宿主版本、section 签名、事件参数、sections/contexts 结构、销毁行为；不把上游注释当成当前宿主事实。
2. 修复第 4 节的注入与监听耦合、已确认的事件签名问题、请求字节限制、selected 回退、context 截断。
3. 为 UI 增加草稿保护和请求响应顺序控制；对共享快照如实标明作用域，避免声称“当前会话”已被隔离。
4. 区分“已保存的配置预览”“最近一次 text() 求值”“最近一次组装结果”，附各自时间或版本；设置变更后把旧快照标为待新请求验证。
5. 整理发布清单和文档；旧迁移计划保留为历史，并指向新的实施基线。

验收：现有测试通过；新增回归覆盖真实缺口；真实宿主完成启用/停用、改设置后发送新请求、切换会话、卸载清理的最小联调；发布预演清单与 README 一致。

### M2：0.5.0 配置管理与独立规则库，预计 3–5 人日

依赖 M1 完成后实施：

1. 提取 `lib/store.js`，集中处理原子写、数据版本、校验、旧数据迁移；保持“落盘失败不更新内存”。Windows 下的保护依赖实际 ACL，文档不把 `0600` 当作 Windows 权限验证结果。
2. 增加 profile 新建、复制、重命名、删除与导入导出，沿用最多 20 项、id 和长度限制；删除当前项时回退到可用项，禁止删空全部配置。
3. 新增独立规则集存储与 CRUD；规则由 profile 显式引用，编辑器清楚显示引用关系。保留旧 `profiles[].rules`，迁移不丢文本、不重复注入。
4. 在实际宿主验证后拆为 `prompt-lab:custom` 和 `prompt-lab:rules`；保持默认拼装内容和顺序兼容。先不强制增加能力协议、尾部提示词与一次性注入。
5. UI 保持现有会话页签，增加规则管理入口和导入预览；沿用增量轮询，避免同时重做 UI 框架和业务模型。

验收：新建→编辑→保存→启用→下一轮组装可核对；规则可复用并独立开关；0.4.8 数据可无损加载；导入失败不污染原状态；重启后数据一致；不覆盖 AGENTS.md/CLAUDE.md。

### M3：本地指令与更完整的观察能力，先做技术验证再估时

- 从可信宿主上下文获取工作目录，提供本地指令文件的只读候选列表、预览和显式勾选；不要直接接受浏览器传入的任意绝对路径作为读文件授权。
- 候选发现与内容读取分离：未选择时只取必要元信息；读取时校验真实路径、目录边界、符号链接、单文件及总量限制；切工作区后旧选择失效。
- 检查宿主是否已经加载相同规则，制定去重方式，避免 AGENTS.md 同时经宿主与插件重复注入。
- 如果事件提供可靠 sessionId，再完成按会话快照；没有标识时保留明确的全局快照，不通过时间或文本猜测归属。
- 增加处理前后“当前快照差异摘要”，包括段名、字数及本次处理统计，仍不建立提示词历史日志。

验收和边界由技术验证结果确定。若拿不到可信 cwd 或 sessionId，分别推迟相应功能，不承诺现有 API 尚未证实的能力。
