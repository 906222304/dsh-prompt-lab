# 项目规范、失败回归与会话适用范围（0.6.3）

## 从项目规范开始，不必重新手写规则

在“AI 创作”中展开“从项目规范选择”，填写工作目录；也可读取会话列表，选择已有会话的项目目录。

- 留空项目根目录时，从工作目录向上查找最近的 `.git`、`.hg` 或 `.svn`；未找到时只看工作目录。也可以明确指定一个包含工作目录的项目根。
- 只查看这条目录链中的 `AGENTS.md`、`CLAUDE.md`、`AGENTS.local.md`、`CLAUDE.local.md`，不递归遍历子目录。按项目根到当前目录排列。
- 展开候选可看路径、目录层级、大小、时间、来源哈希及短预览。勾选后可以“预览所选完整正文”。
- 选择“从材料提取规则”或描述目标后生成，文件内容进入现有 AI 提取/整理流程。仅选定文件及主动带入的其他材料发给所选模型；不会修改项目规范文件，也不自动启用生成的规则。
- “宿主是否已加载”默认为未知。宿主通常有自己的指令加载机制，不能因为扫描到了文件就声称已加载；候选需要检查是否重复照抄原文。优先提炼缺失约束或整理重复，不建议将整份规范原样再注入。

单文件最多 60,000 UTF-8 字节；所选总计最多 90,000 字节、16 个文件，目录链最多 32 层。最终创作请求仍受现有 120,000 字节输入上限约束。无效 UTF-8、超限和实际路径越界会被拒绝。读取前后核对内容哈希；文件变化后须重新扫描选择，不会用旧选择悄悄读取新文件。

关闭工作台会清除尚未提交的文件勾选。已经创建的任务保存冻结原文和来源；继续修改该候选沿用原任务冻结材料，若需要新文件内容应重新选择后生成。

## 如何判断提示词走到了哪一步

“设置 → 诊断”保持默认折叠，增加分层信息：

| 层次 | 能证明什么 |
| --- | --- |
| 已保存 | 当前全局配置和存储版本 |
| 段注册 | 本插件两段在服务中的名称及顺序 |
| 最近求值 | 宿主调用过本插件的动态回调；显示时间、配置版本和可用的会话关联 |
| 最近组装 | 事件观察到的内容及是否过期；只保留最近一份，不是按会话查询历史 |
| 最终请求 | 当前没有取得模型 API 最终请求证据，明确显示未验证 |

当前全局配置的来源列表显示正文、附加规则、共享规则版本与哈希，以及关闭、停用、空正文等排除原因。最近求值使用绑定快照时另有提示，不能把全局预览当作该绑定会话的实际内容。

只有可见组装中本插件段与其他段/上下文都包含同一段规范化原文时才提示重复，忽略空白差异，短于 20 字不判定。不做语义推断，不因另一插件存在就断言重复。快照被截断、过期或没有观察时会说明检查覆盖不足。完整上下文浏览继续使用 dsh-context。

会话关联来自宿主明确的 `context.agent.session.id`，兼容显式 `context.sessionId`；不通过时间、文本或当前页签推测。即使有会话 ID，组装也可能经历后续处理，不能当成最终请求证明。

## 把一次失败变成回归样例

在工作台下方“试跑与迭代 → 将失败对话加入回归集”：

1. 预览会话，明确勾选至少一条用户输入和一条失败的助手回答。
2. 填写纠正意见与验收要求，点击“AI 起草失败回归样例”。只处理选定文字，不采集未选消息、工具输出或推理。
3. AI 生成一条**未保存的训练样例草稿**。用户输入由程序使用所选原文固定，不采用模型改写的输入。
4. 审阅参考资料、评分标准或确定性检查，再勾选“已核对来源、参考资料与检查标准”，保存测试集。没有有效标准不能保存或通过。
5. 配合已有候选执行 A/B 或有预算的优化；优化仍要求另有独立保留样例。

每例保存来源会话 ID、消息 seq/哈希/可见原文、失败输出、纠正意见及确认状态/时间。助手回答属于 `claimed`，人工确认标准不等于验证了助手声称的工具执行。

历史失败固定为 train，不能直接改成 validation。编辑用户输入会使原来源不再匹配：应恢复原文，或明确移除来源作为手工编辑材料。移除来源不会把已经泄漏给改写过程的样例变回独立验证集，需要人工保证独立性。

修改样例内容或评分条件后，界面会取消确认，须重新核对。长消息沿用会话预览的 6000 字上限并标记截断；多条用户输入合计最多 8000 字，失败输出最多 12000 字。错误、取消或格式修复不会自动保存半成品。

## 为指定会话固定一份配置

主页面“会话适用范围”：选择可核对的会话与项目、已保存配置，点击“预览绑定快照”，核对正文、规则、开关与哈希，再“确认仅绑定此会话”。

- 固定的是配置和引用规则的完整内容、版本、顺序与开关。编辑原资产、停用原共享规则、删除原配置或切换全局启用项，不会暗中改变旧快照。
- 更新绑定必须重新预览并确认；预览后源资产、会话项目资料或绑定版本改变会返回冲突。
- 解除绑定后，该会话之后的组装恢复使用全局启用项。保存和解除都不改变全局 selected，也不自动发消息。
- 未绑定会话继续使用全局启用项。子会话不自动继承父会话绑定。
- 绑定按会话 ID 生效，项目目录是来源标签；同一会话内切换工作目录不会自动重新绑定。首版不按 cwd 静默路由配置。
- 最多绑定 20 个会话，记录总计最多 8 MiB。当前入口使用最近 60 个可核对会话；会话服务缺失时不猜测目标。
- 现有环境信息与渠道兼容设置仍是全局设置，不属于绑定快照。关闭插件注入会同时停止所有绑定会话的补充段。

绑定文件损坏时保留原文件并阻止覆盖；带会话身份的补充段暂停，显示错误，避免误用全局配置。修复或恢复正确备份后重新加载服务。

## 场景方案：组合现有能力

“试跑与迭代 → 场景方案”可以保存已保存配置、引用规则、生成/测试/评分模型引用、测试集、共同背景和预算。保存前必须先保存配置及测试集的编辑。

读取列表、选择并预览后，点击“载入场景参数（不启用）”，才会更换编辑器和试跑参数。不会启用配置、切换宿主聊天模型、调用模型或自动运行测试。原草稿未保存时会由界面确认是否放弃。

场景保存冻结内容和源版本。原配置、共享规则或测试集改变后，旧场景仍可查看，但载入会被阻止；可以恢复匹配资产版本，或基于最新资产另存场景。测试集的验证使用次数属于统计，不影响来源匹配，实际试跑仍从服务器读取最新统计。供应商缺失会阻止载入；具体模型可用性还需由宿主实际调用核对。

最多 10 个场景，每份最多 2 MiB。删除场景不删除原配置、规则、测试集或已经发生的任务。

## 文件与回退边界

新增记录只在 `DSH_HOME/prompt-lab/studio/`：

- `bindings.json`：会话绑定的冻结资产。
- `scenarios/c-<UUID>.json`：场景内容与来源快照。
- `suites/s-<UUID>.json`：带失败来源的测试集使用 version 2；旧测试集继续支持 version 1。
- 任务记录沿用 `jobs/`，新增选定项目规范与失败对话材料。

导出配置/规则 JSON 不包含会话绑定、场景、测试集或任务历史。清除创作历史也不删除这些独立资产。

profiles.json 继续采用 schemaVersion 2。回退到 0.6.2 时旧版会忽略新绑定和场景，所有会话恢复全局配置；带来源的 version 2 测试集不受旧版支持，须保留备份，勿用旧版覆盖。恢复 0.6.3 后可继续读取。回退前应备份整个 prompt-lab 数据目录及运行配置，不仅是 profiles.json。
