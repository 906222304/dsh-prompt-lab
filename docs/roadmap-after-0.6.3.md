## 现有事实与缺口

- 0.6.3 的 126 项 Node 测试、浏览器流程、真实宿主隔离联调、安装包解包运行和 0.6.2 回退已通过，见 [交付记录](release-0.6.3.md)。这些证据不等于当前真实运行实例已替换或原生桌面已点击验收。本轮规划不把旧记录补写成新测试通过。
- 当前前端注册 `conversation.view` 时只渲染 Panel，没有将该视图的真实 session 上下文传入。后端虽能按 `agent.session.id` 绑定，用户仍需在列表中选择目标会话。不能拿最近一条组装、最近会话或最后 cwd 当作当前页签身份。
- `lib/studio/scenarios.js` 对过期场景会阻止载入；已有冻结内容，但没有“查看源变化 → 更新引用 → 另存新场景”的引导。
- 当前配置导出只覆盖 profiles/ruleSets，不包含绑定、场景、测试集。完整回退需手工备份整个目录。
- 现有评测固定为补充段文本试跑，支持确定性检查、语义评分和有限优化，不执行工具。没有 Promptfoo 配置/结果适配器或独立运行器。
- 当前测试集每份最多 12 条；实验最多 40 次调用、输出预留总额 24,000 Token。不能直接把大型数据集或多模型矩阵塞入当前单任务循环。

## 第二阶段：0.6.4 使用流程与完整资产包

### P0：当前会话与适用范围清楚可见

- 先验证宿主 conversation 视图、路由或上下文服务的 session 契约，处理空白页签、快速切换、会话关闭与重挂载。
- 契约可靠时默认带入当前会话及项目，页面顶部显示“全局配置 / 会话固定版本”、配置版本、规则数量及待更新状态。
- 绑定、反馈学习和项目来源共用一个明确的目标选择。切换会话后清空不适用的临时消息/文件选择；不得将 A 的候选默认应用到 B。
- 缺少可靠契约时保留显式目标选择，标明身份未知；不按最近活动自动推断。
- 对绑定与全局启用动作显示影响范围。全局环境设置仍需明确标记，不与会话固定资产混淆。

验收：A/B 快速切换、空白会话、已关闭会话、迟到响应、两个面板并开、热重载均不会误绑或错用来源。能直接回答“这个会话接下来用哪份配置”，并保留最终请求证据的现有边界。

### P0：完整资产导入导出

新增独立的便携资产包格式，不改已有配置 JSON 的语义：

| 数据 | 建议默认行为 |
| --- | --- |
| 配置、共享规则、测试集 | 纳入可选择的完整资产导出 |
| 场景 | 连同依赖图、冻结版本与哈希导出 |
| 会话绑定 | 默认不在另一实例自动生效；导入为待重新选择会话的适用记录 |
| 反馈/失败来源原文、任务输出 | 单独选择并预览导出范围；明确包中可能含原文 |
| API Key、供应商凭据、任意宿主目录 | 不纳入资产包；模型只保留引用，目标实例重新核对 |

导入先预览数量、依赖、冲突及源格式，默认追加并重映射 ID；导入场景、测试集不能静默覆盖原资产。缺少模型、会话或依赖时保留为未就绪记录并解释。故障后不能留下半个依赖图，需有预写日志或可验证的暂存提交和恢复协议。导入不触发启用、绑定或模型调用。

完整运行备份与便携导出不同：备份需要可恢复同一实例的目录内容；便携导出需要处理跨实例 ID、会话身份和原文选择。

验收：在空白隔离实例导入可重新打开配置/规则/测试集/场景；重复导入不覆盖旧资产；中途写盘失败可恢复；原配置导入导出继续兼容；未勾选原文不进入导出包。

### P1：把已有步骤连起来

- 保持现有四个页签；工作台围绕“材料 → 候选 → 试跑 → 采用 → 应用范围”展示当前步骤与下一步入口，减少深层嵌套。
- 项目规范选定后直接进入提取/整理；材料摘要显示已选范围及是否需要重新预览。
- 回归草稿保存后可直接选作试跑训练集，并提示独立保留集是否存在；不自动调用下一步。
- 候选采用后可直接预览绑定到明确的目标会话；保存、全局启用与会话绑定仍是不同动作。
- 技术哈希、完整 JSON、历史和诊断继续按需展开；日常主路径展示名称、状态、差异和影响范围。

验收：不手填会话 ID也能完成常用路径；键盘与窄屏可用；来源未确认、草稿未保存和版本冲突都有可执行的下一步，失败保留当前编辑。

### P1：过期场景的更新流程

展示“保存时 / 当前”的配置、共享规则、测试集差异。用户确认采用新引用后另存场景，保留旧场景和历史评测。模型供应商、具体模型和预算变化在同一个预览中核对。未知模型目录可用性明确标为未核验。

验收：旧场景不能静默变化；只有背景或某条规则变化也能定位；更新后测试仍绑定新版本/哈希，不沿用旧版通过结论。

0.6.4 不承诺自动项目路由、语义重复规则自动删除、无人值守学习或自动启用。遇到宿主契约不充分时，按明确目标操作的流程仍应可用。

## 第三阶段：Promptfoo 轻集成

### 为什么放在流程收敛之后

原生评测和优化已经存在。Promptfoo 的新增价值应是标准化交换、外部批量模型矩阵、更丰富断言及 CI 接入；继续由 Prompt Lab 管理资产来源、采用和适用范围。首轮做 eval，不再同时接一套自动优化循环。

截至本次核查，官方 Node 包文档声明 Node >=22.22.0，推荐 Node 24 LTS；`evaluate()` 返回 Eval，再调用 `toEvaluateSummary()` 得到序列化结果。自定义 JavaScript provider 至少实现 `id()` 和 `callApi()`。配置可控制并发、缓存、共享和评测超时。这些是上游现有接口，不表示本插件已经完成适配。

来源：[Node 包](https://www.promptfoo.dev/docs/usage/node-package/)、[Node API](https://www.promptfoo.dev/docs/usage/node-api-reference/)、[JavaScript provider](https://www.promptfoo.dev/docs/providers/custom-api/)、[配置参考](https://www.promptfoo.dev/docs/configuration/reference/)。

### 0.7.0-A：配置与结果互通

- 从冻结的当前版/候选版、测试集及实际模型参数生成可检查的评测包，保留 caseId、split、suite hash、来源版本和范围说明。
- 先支持现有确定性检查。只有语义一致才映射内置断言；不能保证一致的 hasKeys、maxChars 等检查通过固定适配器实现并做对照。unsupported 必须显示，不能丢弃。
- 规则中的模板括号、多行文本和反斜线保留字面量；明确区分 system/user，避免扁平拼接改变测试条件。
- 不向外部配置写入 DSH 凭据；模型引用不可直接翻译时标出需要外部配置的 provider。单纯导出并不能在 DSH 关闭后继续复用其模型服务。
- 结果导入必须核对原评测包哈希、引擎/版本、模型参数、逐例输出、错误和检查明细；来源不匹配的报告仅作为外部历史查看，不作为当前候选的通过证据。
- 首次接入固定 Promptfoo 版本及依赖锁文件；用同一组确定性案例验证原生 runner 与实际 Promptfoo 的语义对应，记录缓存及重试差异。

验收：真实外部运行往返成功；确定性断言一致；不兼容项明确失败或标为未支持；模型、温度和失败计数可追溯。不得将不同引擎的语义评分直接合成一个统一分数。

### 0.7.0-B：可选独立 runner 与 DSH 模型桥

建议进程关系：Prompt Lab 任务控制器 → 独立 Node runner → 固定 provider 适配器 → 受限任务桥 → DSH llm。

- 主插件继续保留无 Promptfoo 运行时依赖和现有 Node 最低要求；runner 单独检查版本与安装状态，未安装时原生试跑继续可用。
- 桥只允许任务预先冻结的模型路由、输入和预算。按任务发放短期随机令牌、到期撤销；不提供通用模型代理，不导出 API Key。
- 含测试回答、评分、格式修复和可控制重试的每次派发均在父进程检查预算。SDK 内部重试/计费不可观察时，必须明确计数边界；不能承诺已有硬计费上限，不能以此上线自动优化。
- runner 退出时终止后续派发，并向正在进行的父进程调用传递取消；仅杀子进程不足以证明远端请求停止计费。
- 首轮仅接受程序生成的评测数据与固定 provider，不加载导入配置中的任意 JS/Python、扩展脚本或动态代码。
- 默认不分享结果；缓存、结果目录与运行环境按任务隔离，避免一次结果误用到另一输入/模型。是否需要遥测/远程生成另按固定版本核对，首版不进入 redteam 生成链路。

上线门槛：真实目标模型和独立评分路由各一条可运行；取消/超时/预算/重复请求/异常退出都有直接证据；运行器崩溃不影响注入；迟到结果不能采用为成功；没有额外 Key 配置仍能通过桥使用已选 DSH 路由。
