## 第一阶段：0.6.5 收口并统一运行版本（优先）

目标：运行插件、源码、安装包和文档使用同一版本，保留明确回退路径。

1. 将默认调整作为 0.6.5 补丁版，核对源文件、初始默认、cordis 配置、第三方署名及包内许可文件；保留旧 0.6.4 安装包与原 manifest。
2. 完成新包解包验证和记录：空目录只有一个默认项；已有用户编辑不被覆盖；当前数据冷加载后不会重新生成 direct/eval；默认正文哈希与当前原文一致。
3. 安装前重新发现当前宿主与依赖路径，备份当时完整数据目录、profile 配置和版本包。原“删除两套之前”的备份也继续保留，防止把不同恢复目标混在一起。
4. 发布源码、替换运行依赖并重载，核对实际前端与后端版本、页面配置数量、正文哈希及 0.6.4 的会话范围/资产包/场景更新入口。源码发布、包构建和运行替换分别记录。
5. 代码回退基线为 0.6.4；活动实例升级前运行基线为 0.6.3，保留其包和完整目录。包含 v3 来源摘要的测试集不能由 0.6.3 读取，回退需恢复相配的数据备份。

完成标准：运行实例能核对到 0.6.5 的实际包；只有用户指定的默认项；原文不变；完整恢复演练通过。重新确认原生桌面操作工具是否可用，原生点击、浏览器流程和宿主 API 的证据分别陈述。

## 第二阶段：验证配置是否真正有用

目标：为“保留原文、补充工程规则或采用精简候选”提供实际依据，当前默认保持原样。

- 选择 4 个有明确通过条件的合成或用户明确选定的任务：错误定位、受约束修改、失败反馈修正、信息不足时的处理。准备输入、参考依据、检查标准，并区分训练和保留材料。
- 第一轮比较“原文”与“原文 + SWE-agent 式复现/回归规则”；第二轮是否比较精简候选，由第一轮失败与开销决定。候选单独保存，不替换当前默认，也不自动增加新的内置配置。
- 固定同一模型、参数、输入、背景与评分规则。先检查可程序判定的条件，再使用明确 rubric；记录格式失败、事实错误、遗漏、调用数、实际 Token usage 与耗时。
- 首轮使用现有两版补充段文本试跑，只能筛查文本表现。随后至少选一个任务，在隔离仓库、独立测试会话和受控数据目录执行真实 Agent 任务，检查文件修改、复现命令和回归结果，再评价工程完成能力。
- 建议首轮所有生成和评分派发合计不超过 16 次，最多两轮合计 32 次；这些是待实施预算，不是本轮已授权或已发生调用。真实 Agent 的工具/模型预算单独定义和记录，不包含在文本试跑统计中。现有单任务 12 样例、40 调用和 24,000 输出预留上限保持。

完成标准：有同输入的前后结果、失败分项和资源开销；保留集未用于改稿；没有实际执行的任务标明未验证。若候选没有稳定改善，保留当前默认，按失败类型迭代。

## 第三阶段：0.7.0-A Promptfoo 数据互通

前提：0.6.5 运行基线稳定，并已经有一组可信的本地测试集。

- 实施时固定并核对 Promptfoo 版本。先支持导出配置/测试输入/受支持断言和导入评测结果，适配字段、阈值和失败语义；不支持的断言明确阻止或标为未评测。
- 导出物记录配置、规则、样例哈希及模型参数；导入前核对来源，旧分数不能套到已改变的提示词或输入上。
- 模型只导出引用，不携带宿主供应商凭据；文件中包含哪些提示词、样例与来源正文，需要在导出前清楚展示。
- 用固定版本 Promptfoo 完成一次真实文件往返，将确定性检查、语义评分、缺失结果、模型错误和过期结果逐项对照；结果只读导入，不自动采用候选或启用配置。

完成标准：同一批实际输入/输出，在两边可解释、可追溯；缺失或不兼容的分数不会被算成通过。先完成数据互通，再单独设计插件内运行器的预算、取消、进程隔离与失败恢复。
