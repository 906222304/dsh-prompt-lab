# 0.6.5 提示词对照与真实 Agent 验证

日期：2026-11-08（Asia/Hong_Kong）。结论：保留现有“越狱破甲”原文。工程增强模块在本次小样本中没有证明值得默认启用；两版都完成了同一个真实仓库修复任务。

## 条件与材料

A 是当前原文，20,969 字符，SHA-256 `111bcf3a26ec7e300d592e298231fe7d611526de3b86c1cdd1002c94d89536ed`。B 是原文加手工冻结的“复现、最小修复、回归、证据和输出格式”模块。候选不是模型生成的，也没有在查看保留样例结果后改写。

模型为当前配置的 `myapi / workbuddy/cn:deepseek-v4.1-flash`，推理强度 max。两版使用相同参数，未指定温度或随机种子，保留供应商默认；因此不是可重复的确定性实验。完整输入、rubric、候选规则与上限见 [protocol.json](../evals/presets-0.6.5/protocol.json)。

使用原生 DSH 0.2.2-rc.1 的官方 headless 组合、AgentRegistry/AgentLoop、SystemPrompt 和真实工具。独立 driver 只负责固定输入、派发预算与证据记录；没有替换模型输出或模拟工具执行。当前用户配置未加入候选，也没有发起真实项目修改。

## 第一轮：四例文本筛查

现有 Studio 两版试跑执行 8 次回答请求和 3 次评分请求，共 11 次。每次回答上限 2048，评分上限 700，输出预留上限 24,000；首轮总派发预算 16，未增加第二轮。

| 样例 | 原文 A | 增强 B | 解释 |
| --- | --- | --- | --- |
| JavaScript 空列表/id=0 修复 | JSON 检查通过，但缺少成对语义评分 | 输出达到 Token 上限，未取得完整答案 | 不据此评价 B 的完整代码正确性 |
| Python 最小修改 | JSON 通过；评分 0.7 | JSON 通过；评分 1.0 | A 未清楚说明未运行验证，B 有明确声明 |
| 失败反馈与证据纠正 | JSON 通过；评分 1.0 | JSON 通过；评分 0.8 | 两者都未伪造测试通过；分差来自同模型的语义判断 |
| 信息不足的诊断 | JSON 通过；成对评分截断 | JSON 通过；成对评分截断 | 不以缺失评分认定胜负 |

执行任务状态 succeeded 表示流程执行到结束；其 result.complete 为 false，accepted 为 false。未完整的汇总分数不能用来选胜者。评分模型与被测模型相同，rubric 本身也存在主观性，不能把该分数当独立事实证明。原始可见回答、检查和失败见 [text-results.json](../evals/presets-0.6.5/text-results.json)。

## 第二部分：真实 Agent 仓库任务

两份独立合成 Git 仓库使用相同初始文件和任务。任务是修复 Python subtotal：None 输入返回 0、缺省数量为 1、数量为 0 不得被覆盖、负数量抛 ValueError、不修改输入。只允许修改 pricing.py，不得改测试。运行前两份仓库均能复现 2 项失败和 1 项错误。

| 指标 | 原文 A | 增强 B |
| --- | --- | --- |
| 原生 Agent 结束原因 | completed | completed |
| 实际模型服务层派发 | 6 | 7 |
| 实际工具调用 | 7 | 10 |
| 观测耗时 | 21.224 秒 | 26.889 秒 |
| 原有测试，独立重跑 | 6/6 通过 | 6/6 通过 |
| 评估方补充边界检查 | 7/7 通过 | 7/7 通过 |
| 原测试工作区字节对比 | 未改动 | 未改动 |
| 最终源码差异 | 仅 pricing.py | 仅 pricing.py |
| 最终补丁 | 与 B 相同 | 与 A 相同 |

持久化事件包含真实 pwsh/read/glob/write/edit 调用与工具结果。两份 system/message 均包含原文，只有 B 包含增强模块；request/header 的路由、推理强度和 maxTokens=2048 一致。测试文件使用 Git filters 恢复工作区换行后作字节比较，避免把 Windows CRLF 与仓库 LF 的差异误记为改动。

两版都先运行失败复现，再修改并重新执行单元测试；评估方在 Agent 结束后再次执行测试和额外边界检查。没有根据助手自述判定成功。测试仓库之外没有代码修改。最终可见回答、工具参数、补丁和独立核验见 [agent-results.json](../evals/presets-0.6.5/agent-results.json)。

在正式计量前，一个只影响评估器哈希记录的初始化错误在零模型派发时被修正，失败记录保留于本地；不将其算作模型能力失败，也不隐藏实际模型调用。

## 结论与保留项

这份合成任务说明两版都具备在本机配置下完成该代码修复的能力，不说明所有工程任务或所有模型都有效，也不证明所谓破甲能力。当前没有证据支持自动替换默认或继续扩写规则；保留原文。后续若继续优化，先解决当前推理强度与评分输出上限的匹配，再补充真实失败案例做独立复测。

评测使用隔离数据目录、会话和仓库。没有把 API Key 或凭据文件复制到评测目录；只携带白名单模型元数据与凭据引用，由官方凭据服务在进程内解析现有配置。自动审批曾拒绝完整供应商配置落盘，该操作未执行，随后改用上述方式。

本地完整运行日志可能含模型推理块，因此不提交；公开材料只保留协议、可见输出、工具行为、测试和派发计量。机器相关临时 driver/数据不随 npm 包发布。复现材料见 [evals/presets-0.6.5](../evals/presets-0.6.5/README.md)。
